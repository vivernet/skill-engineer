# Установка и проверка

## Путь и формат

Клонируй репозиторий или распакуй архив целиком вместе с `scripts/`, `references/`, `assets/`, `agents/`. Нельзя копировать только SKILL.md: тогда потеряются локальные проверки и дополнительные инструкции. Если GitHub назвал папку архива, например, `skill-engineer-main`, переименуй её в `skill-engineer`: имя должно совпадать с `name` в SKILL.md.

## Codex

Пользовательский каталог в macOS, Linux и Windows: `~/.agents/skills/skill-engineer/`. Символ `~` обозначает домашний каталог пользователя; в Windows PowerShell это `$HOME`, в командной строке — `%USERPROFILE%`.

В проекте: `<repo>/.agents/skills/skill-engineer/`. Выбирай **один** уровень установки, чтобы не получить дубли. Через Codex: `$skill-engineer Создай навык ...`. Дополнительные поля для UI находятся в `agents/openai.yaml`.

## Claude Code

Размести полную папку навыка в `~/.claude/skills/skill-engineer/` для локальных проектов пользователя или в `<repo>/.claude/skills/skill-engineer/` для одного проекта. Перед копированием проверь, нет ли там существующей версии, и сохрани чужие изменения. Claude Code также поддерживает ссылку на папку навыка в одном из этих расположений; сначала проверь политику ссылок среды и доступ к целевому каталогу. Локальные скрипты проверки принимают реальный каталог, поэтому при использовании ссылки передавай им путь к её цели.

В Claude Code вызови `/skill-engineer` или дай подходящий запрос без имени. По умолчанию разрешены и ручной, и автоматический вызов; не добавляй `disable-model-invocation`, `context: fork` или списки инструментов без конкретной потребности. Если навык не появляется, проверь расположение, одноимённые навыки и ограничения сессии. Настройки `agents/openai.yaml` относятся к Codex, а не к Claude Code.

## Hermes

В macOS и Linux стандартный каталог — `~/.hermes/skills/skill-engineer/`. В Windows путь зависит от активного профиля; в некоторых установках используется `AppData\Local\hermes\skills`. Если эта папка уже используется твоими навыками, распаковывай туда:

`C:\Users\<USER>\AppData\Local\hermes\skills\skill-engineer\`

У других установок/профилей путь может быть `C:\Users\<USER>\.hermes\skills\skill-engineer\`. Приоритет имеет **реально используемая текущим профилем папка**, а также `skills.create_dir` и `skills.external_dirs` из конфигурации. У Hermes допускаются категории (`skills/productivity/skill-engineer`), но **папка самого навыка** должна называться `skill-engineer`.

Для общего расположения с Codex добавь путь в существующий список `skills.external_dirs` в Hermes `config.yaml`, сохранив остальные пути и настройки. Если раздела или списка нет, создай его; следующий фрагмент показывает только соответствующую часть файла, а не замену всей конфигурации:

```yaml
skills:
  external_dirs:
    - ~/.agents/skills
```

Однако локальный Hermes навык с таким же именем может перекрыть внешний. При общем пути контролируй изменения с обеих сторон: это не read-only.

## После копирования

Запускай команды из корня установленной папки `skill-engineer`.

**macOS и Linux:**

```sh
python3 -X utf8 -B scripts/validate_skill.py . --strict
python3 -X utf8 -B scripts/audit_skill.py .
```

**Windows PowerShell:**

```powershell
py -3 -X utf8 -B scripts/validate_skill.py . --strict
py -3 -X utf8 -B scripts/audit_skill.py .
```

Убедись, что навык появился в списке у агента. Для Hermes доступны `hermes skills list` и `/skill-engineer`; для Claude Code — `/skill-engineer`; для Codex — `$skill-engineer`. При одноимённых навыках проверь выбранный путь средствами среды; если это не удалось, не утверждай, что загружена нужная копия. Затем проверь запрос на создание или аудит навыка и близкий запрос без этой задачи, например обычное ревью кода: наблюдай, был ли скилл выбран и какие действия выполнены. Наличие в списке не доказывает автоактивацию. Если среда или запуск агента недоступны, укажи соответствующую проверку как `NOT RUN`.

## Работа над существующими навыками

- Если каталог находится в Git, проверь `git status --porcelain` / `git diff`. Вне Git зафиксируй отсутствие репозитория. В обоих случаях сохрани копию затрагиваемых файлов вне навыка.
- Не замещай чужую папку новым архивом «поверх» без сравнения изменений.
- Сначала `validate`, `audit`, `eval init`; затем patch без очистки или принудительных операций.
