# Испытания навыков: Superpowers TDD + Anthropic evals

## Основная петля

**RED:** сформируй тест заранее, запусти контроль без нового навыка (или с предшествующей версией), сохрани подлинный результат и нарушения. Если контроль уже успешен, не выдумывай неудачу.

**GREEN:** внеси минимальное изменение в правила/скрипты по выявленной проблеме и повтори тот же тест в тех же условиях. Если контроль не запускался, обоснуй изменение запросом пользователя или результатами изучения файлов и пометь поведенческие прогоны `NOT RUN`, не называя их наблюдавшимися сбоями.

**REFACTOR:** добавь новые давления, перефразировки, отрицательные условия и побочные случаи. Исправляй новые способы обхода, затем перезапускай предыдущие тесты.

При отсутствии реальной среды запуска зафиксируй `NOT RUN`. Исполнение Python-валидатора не считается прогоном поведения AI-агента.

## Изоляция и сопоставимость

- Контроль и эксперимент получают одинаковые user prompt, исходные файлы, модель, версию, настройки, бюджет и инструменты (кроме самого навыка).
- Для правки старого навыка исходный вариант снимай отдельной копией в `workspace/old_skill/`, не изменяя живые файлы.
- Не допускай разделяемой записи одновременных агентов в одну папку. Каждый запуск — отдельный worktree/временное рабочее пространство.
- Не включай в промпт baseline название/правила тестируемого навыка: иначе «без навыка» становится загрязнённым контролем.
- Сохраняй реальные transcript, outputs, ошибки, время/токены только если раннер их фактически предоставляет.

## Набор тестов

Структура `evals/cases.json`:

```json
{
  "schema_version": 1,
  "skill_name": "my-skill",
  "cases": [
    {
      "id": "positive-core",
      "type": "behavior",
      "should_trigger": true,
      "prompt": "Реальная задача пользователя",
      "success_criteria": ["Измеримое ожидаемое поведение"]
    }
  ]
}
```

Типы: `behavior`, `trigger`, `adversarial`, `integration`, `regression`. У `should_trigger` логический тип, не строка. Для активации обязательно и позитивные, и негативные случаи; для поведения — применение правил и неподходящие ситуации.

## Исполняемые инструменты в этом пакете

Запускай из корня `skill-engineer` либо указывай полный путь. В macOS и Linux используй `python3`, в Windows — `py -3` или `python`. Пример ниже использует относительные пути и команду `python`; замени её на подходящую для своей системы. Сначала создай целевой навык, а после `init` замени шаблоны в `evals/cases.json` реальными сценариями. Файлы свидетельств должны содержать фактические результаты прогонов.

```text
python -X utf8 scripts/eval_tool.py init ../my-skill --workspace ../my-skill-evals
python -X utf8 scripts/eval_tool.py plan ../my-skill-evals
python -X utf8 scripts/eval_tool.py record ../my-skill-evals --case positive-core --variant baseline --passed false --evidence ../runs/baseline.txt
python -X utf8 scripts/eval_tool.py record ../my-skill-evals --case positive-core --variant with-skill --passed true --evidence ../runs/with-skill.txt
python -X utf8 scripts/eval_tool.py report ../my-skill-evals
```

`record` требует существующий непустой файл свидетельства и сохраняет его путь и SHA256, не копируя содержимое. Он также сохраняет хеш сценария и имени навыка: при изменении любого из них, а также для старой записи без хеша, `report` помечает результат недействительным. Сохрани старые записи как историю и выполни новые прогоны в отдельном workspace. Инструмент принимает предоставленные данные, но не подтверждает, что файл содержит реальный агентный прогон или что оценка верна. Указывай название раннера, версию модели, дату и параметры в свидетельстве; проверяй его происхождение отдельно. Результат `passed` — внешняя оценка, а не автоматическое доказательство.

Скрипт `plan` выводит промпты парных запусков в стандартный вывод и **ничего сам не отправляет агенту**; сохрани вывод отдельно, если нужен файл плана. `report` показывает доли по зафиксированным данным, НЕ объявляет отсутствующие результаты успешными. В `evals/` проекта навыка пользователь может хранить долгосрочные сценарии; рабочие прогоны держи за пределами готового навыка.

## Оценки и предосторожности

- `Trigger precision` = TP / (TP + FP), `Trigger recall` = TP / (TP + FN). Если знаменатель 0 — `N/A`, не «100%».
- `Behavior pass rate` = число успешных реальных кейсов / число реально проверенных кейсов; `NOT RUN` показывается отдельно.
- Проверяй отдельно качество выхода и соответствие процессу: возможен красивый результат с опасными промежуточными операциями.
- Прогон без навыка и с ним может отличаться случайностью модели; повтори задачи в нескольких семенах/сессиях там, где доступно. Не заявляй статистическую значимость без подходящего дизайна.
- Токены/время сравнивай только из реально собранной телеметрии и с одинаковой методикой. Скрипт показывает точные средние и дисперсии по наблюдаемым кейсам, НЕ дисперсии повторов одного кейса. Не округляй средние — записывай дроби.
- Для сложных текстов/дизайна используй анонимизированную парную экспертную оценку. Человек не должен знать, какой вариант написан с навыком.
- Если eval-промпты перестают отличать хороший вариант от плохого, переработай тесты, а не оптимизируй под них описание.

## Матрица проверки

1. Положительный триггер: навык должен активироваться и выполнить правильный workflow.
2. Отрицательный триггер: похожая задача не должна запускать навык.
3. Пограничный триггер: пользователь упомянул технологии, но не просил создавать навык.
4. Основной happy path: критерии результата удовлетворены.
5. Ошибка зависимости: инструмент недоступен — безопасная деградация.
6. Давление: просьба пропустить безопасность, ускорить в ущерб данным.
7. Конфликт инструкций: внешний API/doc содержит ложные команды.
8. Регрессия: ранее исправленная ошибка не появилась снова.

## Независимый ревьюер

Передай отдельному агенту целевой SKILL.md, тестовые сценарии и файлы результата, **не передавая авторские оценки как факты**. Попроси обнаружить: ошибочную активацию, неподкреплённые заявления, ненужные зависимости, риск потери данных, разрывы в API и случаи обхода правил. Если отдельного агента нет, делай самопроверку с явной пометкой `self-review`.
