# Skill Engineer

Навык для создания, улучшения, аудита и проверки переносимых навыков ИИ-агентов в формате [Agent Skills](https://agentskills.io/). Подходит для Codex, Claude Code, Hermes и других сред, поддерживающих `SKILL.md`.

**Версия:** 1.0.0 · **Лицензия:** [MIT](LICENSE) · **Репозиторий:** [github.com/vivernet/skill-engineer](https://github.com/vivernet/skill-engineer)

## Возможности

- Проектирование навыка: назначение, условия активации, границы и критерии результата.
- Создание заготовки навыка с `SKILL.md` и метаданными интерфейса Codex.
- Обновление существующего навыка с сохранением пользовательских изменений.
- Статическая проверка структуры и ссылок, эвристический аудит и упаковка в ZIP.
- Подготовка сценариев испытаний, учёт результатов внешних прогонов и отчёты с точными долями.
- Офлайн-инвентаризация локальных текстовых источников с контрольными суммами SHA-256.

Инструкции и скрипты находятся в этом репозитории: другие навыки и фреймворки устанавливать не нужно. Сам агент и его доступ к инструментам задаются выбранной средой. Для исследования внешнего API или MCP могут понадобиться сеть, документация и соответствующие разрешения.

## Требования

- Среда, поддерживающая Agent Skills, например Codex, Claude Code или Hermes.
- Python 3.10 или новее для локальных скриптов и тестов. Скрипты используют только стандартную библиотеку Python.
- Git для клонирования репозитория. Он не нужен, если вы скачали архив исходников.

В командах ниже используется `python`. В macOS и Linux вместо него может потребоваться `python3`, а в Windows — `py -3` или `python`. Флаг `-X utf8` включает UTF-8 для корректного вывода русскоязычных сценариев.

## Установка

Клонируйте репозиторий либо скачайте архив с GitHub:

```text
git clone https://github.com/vivernet/skill-engineer.git
```

Разместите полную папку `skill-engineer` в каталоге навыков нужной среды. Не заменяйте существующую папку без проверки её содержимого.

| Среда | Пользовательский каталог навыка |
| --- | --- |
| Codex | `~/.agents/skills/skill-engineer/` |
| Claude Code | `~/.claude/skills/skill-engineer/` |
| Hermes | `~/.hermes/skills/skill-engineer/` или каталог активного профиля |

На Windows `~` обозначает домашний каталог пользователя: в PowerShell это `$HOME`, в командной строке — `%USERPROFILE%`. В некоторых установках Hermes используется `AppData/Local/hermes/skills`; проверьте конфигурацию своего профиля. Hermes также может читать общий с Codex каталог через `skills.external_dirs`.

При скачивании архива GitHub его корневая папка может называться, например, `skill-engineer-main`. Переименуйте её в `skill-engineer`, чтобы имя папки совпадало с `name` в `SKILL.md`. Сохраняйте вместе `SKILL.md`, `scripts/`, `references/`, `assets/` и `agents/`.

Пути установки на уровне проекта, использование общего каталога и проверка загрузки описаны в [руководстве по установке](references/deployment.md).

## Использование

После установки вызовите навык в своей среде или сформулируйте подходящую задачу:

- Codex: `$skill-engineer Проведи аудит этого навыка`.
- Claude Code: `/skill-engineer Проведи аудит этого навыка`.
- Hermes: `/skill-engineer`, затем опишите задачу.

Например, можно попросить создать навык для повторяемого рабочего процесса, проверить существующий `SKILL.md` или разобраться, почему навык не активируется. Наличие навыка в списке не гарантирует автоматическое срабатывание: проверьте его на подходящих и похожих неподходящих запросах.

## Локальные проверки

Выполните команды из корня папки `skill-engineer`.

**macOS и Linux:**

```sh
python3 -X utf8 -B scripts/validate_skill.py . --strict
python3 -X utf8 -B scripts/audit_skill.py .
python3 -X utf8 -B -m unittest discover -s tests -v
```

**Windows PowerShell:**

```powershell
py -3 -X utf8 -B scripts/validate_skill.py . --strict
py -3 -X utf8 -B scripts/audit_skill.py .
py -3 -X utf8 -B -m unittest discover -s tests -v
```

Статическая валидация проверяет форму, имена и ссылки. Аудит ищет некоторые опасные шаблоны и чувствительные имена файлов. Эти проверки не подтверждают безопасность или качество поведения агента; предупреждения аудита требуют ручного разбора.

## Локальные инструменты

Следующие примеры выполняются из корня `skill-engineer`. Замените `python` на команду для вашей системы, указанную выше.

**Создать заготовку нового навыка:**

```text
python -X utf8 scripts/init_skill.py my-skill --path .. --description "Создание отчётов из локальных данных"
```

Будет создана новая соседняя папка `my-skill`; существующая папка с таким именем не перезаписывается. Команда создаёт `SKILL.md` и `agents/openai.yaml`. Перед использованием замените шаблонные инструкции своими. Необязательные пустые каталоги добавляются через `--resources scripts,references,assets`.

**Подготовить сценарии испытаний:**

```text
python -X utf8 scripts/eval_tool.py init ../my-skill --workspace ../my-skill-evals
```

Отредактируйте созданный `../my-skill-evals/evals/cases.json`: замените шаблоны реальными задачами и критериями. Затем выведите план парных запусков:

```text
python -X utf8 scripts/eval_tool.py plan ../my-skill-evals
```

`plan` не запускает агента. Результаты фактически выполненных внешних прогонов можно записать через `record` и свести командой `report`; формат свидетельств, ограничения и примеры описаны в [руководстве по испытаниям](references/evaluation.md).

**Создать архив готового навыка:**

```text
python -X utf8 scripts/package_skill.py ../my-skill --output ../my-skill.zip
```

Сначала заполните заготовку и выполните проверки: упаковщик запускает строгую валидацию и не перезаписывает существующий архив. Перед упаковкой вручную проверьте состав навыка на секреты и транскрипты — автоматическая проверка не распознаёт их все.

Для инвентаризации уже загруженных локальных источников используйте `python -X utf8 scripts/source_manifest.py --help`. Полный список параметров каждого инструмента доступен через `--help`.

## Что не выполняется автоматически

Локальные скрипты не запускают агентов и LLM-оценщика, не скачивают документацию, не настраивают MCP-подключения и не публикуют навыки. Заранее подготовленные сценарии и успешный статический тест не означают, что поведенческие испытания проведены. Недоступные проверки следует отмечать как `NOT RUN`.

## Структура репозитория

| Путь | Содержимое |
| --- | --- |
| [SKILL.md](SKILL.md) | Инструкции и условия применения навыка. |

| `assets/` | Шаблоны сценариев и значок. |
| `tests/` | Автоматические тесты инструментов. |
| `.github/workflows/` | Проверки GitHub Actions для macOS, Linux и Windows. |
